# Design Management My Team

The 29 October explanation defines My Team as a management view of saved SPOC daily entries. A Technical Director retains their login role. Only a saved department or designation containing Design Management or Design Mgmt enables this dashboard for a TD. Other TDs retain their directory. The explicit Design Management Head, Founding Director and Working Director roles can also open it, within their own saved reporting line.

The API rechecks the current active login and reporting scope for every request. Coordinator logins can read only their own reflected data; management writes require a permitted head. Duplicate active SPOC logins and conflicting employee links are omitted for HR review. No name-specific exception, company roster seed, employee import or automatic reporting relationship is added.

Source records are SpocEntry, Project, approved current SpocAllocation, CoordinationItem, Rfi, Revision, Meeting and DesignWorkflow. Project.activation.spoc is the authoritative current SPOC; one approved active legacy allocation is a fallback. Conflicting legacy allocations require reconciliation. Reassignment uses a version/current-SPOC compare-and-set, requires a reason and retains append-only DesignTeamEvent history. Prior allocation rows remain stored with active=false. The project audit middleware ignores unmatched updates/deletes so a rejected concurrent reassignment cannot be attributed a successful audit change. Old SPOC access ends when the authoritative project pointer changes. Admin activation state remains unchanged.

Project.coordinationStatus stores Delayed, Awaiting info and Ready for billing while operational Project.status stays Active. This preserves existing active-project work-entry queries. On Hold and Completed retain operational precedence. No management status sets a billing approval or stage-completion decision.

The dashboard uses seven Monday-to-Friday working days in Asia/Kolkata, excluding published Holiday records. Approved leave and travel are labelled separately; existing saved entries always retain their actual hours. The attendance policy remains independent. The standard day is eight hours; stale-update flags are 21 days for a SPOC and 30 days for an in-progress workflow step. These are the specification defaults and require company acceptance. DESIGN_TEAM_CAPACITY can set a positive numeric capacity; the default is ten points. High/Medium/Low complexity use 3/2/1 points, missing complexity uses 2, On Hold halves points and Completed uses zero. Light is below 5, Balanced is 5 through 8 and Heavy is above 8.

Read-only history of work outside current allocation remains available for authorized SPOCs' own saved entries. It exposes minimal project information and no foreign contacts, follow-ups or management authority. Activity history combines actual daily entries with management events. Coordination/RFI closure updates the saved source status; revision and meeting-action follow-up closures use an append-only overlay, retaining existing approval/completion policy. MOM circulation stores actor/time. Workflow changes retain existing matrix and untouched steps.

The existing daily-entry screen and sign-out man-hour gate are unchanged. Dashboard totals read saved work, never prototype hours. Saved daily entries may include legacy work areas and retain them. The new audit/event records are immutable through model operations and have no edit/delete API. Normal business-record writes and event writes are sequential, following existing project-audit behavior; distributed transaction atomicity during a database outage is not claimed.
